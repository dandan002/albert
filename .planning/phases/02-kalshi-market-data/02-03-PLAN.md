<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments to pipeline | User-supplied dates, run ID, roots, and series ticker control requests and local outputs. |
| Pipeline source pages to manifests | Raw source metadata is persisted for auditability. |
| Normalized tables to downstream phases | Bad quality flags or missing provenance can corrupt model/backtest inputs. |
| Optional live API run to local cache | Public network data is untrusted and must be cached with provenance. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `run_kalshi_discovery` output paths | mitigate | Use `normalized_cache_path()` for every table and `run_manifest_path()` for manifests; no manual path composition from source, endpoint, table, or run identifiers. |
| T-02-02 | Information Disclosure | CLI and manifest parameters | mitigate | Keep the command public-data only by default, do not accept API key options, and rely on existing config/manifest secret-like key rejection for persisted parameters. |
| T-02-03 | Tampering | date filters and source metadata | mitigate | Require explicit `--start-date` and `--end-date`, preserve endpoint parameters, fetched time, and covered ranges per source page, and pass routing tests spanning historical/live windows. |
| T-02-04 | Tampering | quality and pipeline outputs | mitigate | Use fixture-backed normalization, preserve raw payloads, emit skipped-market rows for ambiguous mappings, and write quality rows for missing outcomes or price history. |
</threat_model>
