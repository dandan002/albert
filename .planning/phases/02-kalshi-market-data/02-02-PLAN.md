<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Raw Kalshi JSON to normalized schemas | External payloads may contain unexpected fields, missing fields, or changed fixed-point shapes. |
| BTC market mapping to eligible outputs | Ambiguous market titles/subtitles can corrupt DATA-01 discovery outputs. |
| Missing source observations to data-quality rows | Missing outcomes, prices, or orderbooks must not be silently hidden. |
| Normalized source paths to downstream consumers | Provenance paths become audit inputs for later phases. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | normalized provenance path fields | mitigate | Store source raw paths as values only; downstream file writes use `normalized_cache_path()` in Plan 02-03 and never table-derived manual paths. |
| T-02-02 | Information Disclosure | normalized rows | mitigate | Normalizers do not accept or emit API keys; manifest/config secret-like key rejection remains the persisted-parameter control. |
| T-02-03 | Tampering | timestamp parsing | mitigate | Normalize all source timestamps to UTC-aware datetimes and preserve source endpoint/raw path so cutoff filters can be audited. |
| T-02-04 | Tampering | schemas and normalizers | mitigate | Use `ConfigDict(extra="forbid")`, fixture-backed live/historical validation, skipped-market rows for ambiguous BTC mappings, and quality rows for missing outcomes/history. |
</threat_model>
