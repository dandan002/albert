<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Endpoint names to filesystem | Endpoint segments determine raw cache directories. |
| Kalshi response to local cache | External JSON is written locally as provenance evidence. |
| Date windows to endpoint selection | Incorrect cutoff routing can mix historical/live semantics. |
| Request parameters to manifests | Parameters later become manifest source metadata. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `KalshiClient.get_json_page` | mitigate | Reuse `sanitize_segment()` and `raw_cache_path()` for every raw page; only allow endpoint segments from `ALLOWED_ENDPOINT_SEGMENTS`. |
| T-02-02 | Information Disclosure | client request parameters | mitigate | Keep Phase 2 client public-data only by default, add no API key options, and rely on existing manifest secret-like key rejection when pages are recorded. |
| T-02-03 | Tampering | `plan_market_windows`, `plan_trade_windows` | mitigate | Preserve endpoint, request parameters, fetched time, and covered ranges in `FetchedPage`; tests span cutoff windows and verify family-specific cutoff fields. |
| T-02-04 | Tampering | client payload handling | mitigate | Preserve raw JSON pages exactly in cache for later schema drift inspection; fixture-backed tests validate expected live/historical shapes before normalization. |
</threat_model>
