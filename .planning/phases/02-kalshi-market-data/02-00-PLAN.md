<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI input to filesystem paths | `--run-id`, endpoint/table names, and cache/run roots affect local file writes. |
| Kalshi API payloads to normalized rows | External JSON is untrusted and may drift or contain ambiguous mappings. |
| Request parameters to manifests | Parameters are persisted for provenance and must not include secrets. |
| Time-window requests to research outputs | Incorrect cutoff selection can leak future or unavailable data into downstream research. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | cache path tests | mitigate | Tests require use of `sanitize_segment()`, `raw_cache_path()`, `normalized_cache_path()`, and `run_manifest_path()`; unsafe endpoint segments must raise before file writes. |
| T-02-02 | Information Disclosure | manifest and fixture tests | mitigate | Tests keep Phase 2 public-data only by default and assert secret-like keys are rejected by existing config and manifest models. |
| T-02-03 | Tampering | routing tests | mitigate | Tests cover `market_settled_ts`, `trades_created_ts`, spanning windows, endpoint parameters, fetched time, and covered ranges per source page. |
| T-02-04 | Tampering | fixture-backed normalization tests | mitigate | Fixtures cover live/historical schema drift, ambiguous BTC mapping, missing outcomes, skipped-market rows, quality rows, and raw payload preservation. |
</threat_model>
