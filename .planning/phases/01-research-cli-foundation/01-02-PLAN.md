<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Source labels/parameters -> filesystem paths | Dynamic source, endpoint, table, and run identifiers become path segments or hash inputs. |
| Ingestion metadata -> manifest JSON | Later phases will pass endpoint parameters and output references into persisted manifests. |
| Run root/cache root -> local filesystem | Helpers create directories and write manifest files under configured roots. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Tampering | `src/albert/cache.py` | mitigate | Allowlist path segments with `SAFE_SEGMENT`, hash arbitrary parameters instead of using them in path segments, and assert root containment with `_ensure_under_root`. |
| T-01-05 | Repudiation | `src/albert/manifest.py` | mitigate | Require endpoint, parameters, fetch time, covered time range, raw path, normalized output path, command, config path, cache root, and run root in Pydantic models. |
| T-01-06 | Information Disclosure | `src/albert/manifest.py` | mitigate | Reject secret-like keys in source and run parameter mappings; tests include `api_key` and `token` rejection. |
| T-01-07 | Denial of Service | `write_manifest` | accept | Phase 1 writes small local manifest JSON only; no unbounded network input or bulk dataframe writes are introduced. |
</threat_model>
