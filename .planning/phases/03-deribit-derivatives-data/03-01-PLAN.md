<objective>
Build the Deribit data ingestion layer: client, fixture payloads, instrument discovery pipeline, OHLC/ticker fetching, and CLI command. This plan establishes the fetch-and-cache layer that mirrors the Kalshi client pattern but simplified for Deribit's single-API architecture (no live/historical routing per D-07). The CLI provides `albert ingest deribit fetch` with `--start-date`, `--end-date`, and `--near-dated-days` parameters per D-09/D-10. Raw API responses are cached as JSON with full provenance through the existing `raw_cache_path()` and `RunManifest` contracts.

Purpose: Enable reproducible Deribit data fetching so Phase 4 can align observations with Kalshi contract windows using only pre-decision timestamps.
Output: Working Deribit client, fixtures, instrument discovery pipeline, and CLI command that caches raw responses.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI → Deribit API | Untrusted external API — all inputs are public, no auth credentials, but responses must be validated |
| API response → Raw cache | External data saved to local filesystem — must validate JSON structure before caching |
| Raw cache → Normalization | Cached data fed into normalization pipeline — must not crash on malformed data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

</threat_model>
